## Visão geral

O OpenSRE consegue mascarar identificadores de infraestrutura, como nomes de pods, clusters, hosts, contas, serviços, endereços IP e e-mails **antes** de enviar texto para um modelo de IA externo. Em determinados caminhos de execução, os valores originais são restaurados antes de apresentar a resposta.

**O mascaramento vem desativado por padrão** e pode ser ativado por variáveis de ambiente, sem editar o código.

## Como funciona

1. Quando habilitado em um fluxo compatível, o OpenSRE troca identificadores por marcadores estáveis, como `<POD_0>`, `<NAMESPACE_0>` ou `<CLUSTER_1>`.
2. O modelo recebe o texto mascarado, sem os identificadores originais naquele envio.
3. Quando o mapa `masking_map` está disponível, os valores podem ser restaurados no estado e nas respostas.
4. Alguns canais de mensagens, como Slack, podem executar uma restauração final.

O mesmo identificador recebe o mesmo marcador durante uma sessão. **A cobertura não é universal:** na implementação documentada, o mascaramento depende de caminhos específicos, como algumas ferramentas de correção do GitHub e Sentry e certos fluxos de execução de agentes por CLI. Verifique seu caminho de execução antes de confiar nessa proteção.

## Variáveis de ambiente

| Variável | Padrão | Finalidade |
| --- | --- | --- |
| `OPENSRE_MASK_ENABLED` | `false` | Ativa o mascaramento com `true`, `1`, `yes` ou `on`. |
| `OPENSRE_MASK_KINDS` | `pod,namespace,cluster,hostname,account_id,ip_address,email,service_name` | Lista de tipos separados por vírgula. Tipos desconhecidos geram aviso. |
| `OPENSRE_MASK_EXTRA_REGEX` | Vazio | Objeto JSON opcional de rótulos e expressões regulares para identificadores personalizados. |

## Restauração e guardrails

Para detectores internos e padrões personalizados compatíveis, o projeto descreve a possibilidade de restaurar os valores originais após o mascaramento. Há um exemplo em `tests/masking/test_integration_with_k8s_fixture.py`.

Os **guardrails** complementam o mascaramento. Enquanto o mascaramento reversible pode recuperar identificadores, os guardrails aplicam bloqueios e substituições definitivas por `[REDACTED]` para determinadas informações sensíveis, como chaves de API.

## Exemplo de configuração

```bash
export OPENSRE_MASK_ENABLED=true
export OPENSRE_MASK_KINDS=pod,namespace,cluster,hostname
opensre ask "why is the checkout pod crash-looping?"
```

Tradução da pergunta: "Por que o pod do checkout está reiniciando continuamente?"
